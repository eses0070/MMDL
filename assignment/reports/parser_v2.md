# 파서 v2 — MMMU 객관식 재채점

저장된 Qwen3-VL 응답 중, 기존에 최종 답을 추출하지 못한 객관식 46개를 다시 처리했다. **6개에서 답을 추출했고 4개가 GT와 일치하여 전체 점수가 564/900에서 568/900으로 바뀌었다.**

|---|---:|---:|
| 전체 정답 | 564/900 | **568/900** |

이번 대상은 객관식 46개다. 주관식 53개와 이미 추출한 객관식 35개를 포함한 나머지 854개는 변경하지 않았다.

## 환경·재현

Python 3.10 이상, 기본 라이브러리만 사용한다. 저장된 모델 응답과 Qwen3-8B judge 응답을 재사용하므로 새 VLM 추론, 새 judge 호출, GPU 사용, 유료 API 호출은 없다. CPU 테스트 69개와 Git 배포 폴더에서의 재실행으로 검증했다.

```bash
cd experiments/parser_v2
python3 -B -m unittest discover -s tests -p 'test_*.py' -v
python3 -B replay.py --limit 0 --output-dir results/mc46_run1
```

## 채점 방식

최종 답을 GT 없이 추출한 뒤 각 선택지와 대응한다. 숫자·단위·백분율은 이전 AE의 정확한 수량 비교 규칙을 사용한다. 규칙으로 충분하지 않으면 원래 Qwen3-8B 응답의 답 제안과 모델 원문의 명시적 최종 선택이 일치하는지 검사한다. 과거 judge의 `correct/incorrect` 판정을 그대로 재사용하지 않는다. 추출한 선택지 키를 확정한 다음에만 GT와 비교한다.

실제 회복된 6개는 문자·선택지 내용 대응 2개와 저장 judge 제안/최종 답 근거 확인 4개다. **숫자 환산으로 새롭게 해결된 문항은 0개**이며, 수량 비교기 자체의 성능 향상으로 해석하지 않는다.

## 새로 추출한 6개의 실패 원인과 보완

**남은 46개 중 6개를 추출했고, 40개가 남았다.** 이 6개는 모두 원래 생성이 `finish_reason=stop`으로 정상 종료되었고, 응답에 최종 선택이 있었다. 모델 답변을 다시 생성하거나 정답으로 고친 것이 아니라, 기존 규칙 파서가 놓쳤던 최종 선택을 읽어낸 것이다.

| 문항 | 직전 규칙 파서에서 막힌 부분 | 파서 v2의 처리 | 추출 / GT | 최종 답 채점 |
|---|---|---|---|---|
| Agriculture_12 | `Final Answer: D. Peristalsis` 뒤에 주석이 붙어 마지막 줄이 답이 아니었다. | 명시적 최종 답 D와 저장 judge의 답 제안이 일치하는지, 뒤의 주석에 새로운 선택이나 철회가 있는지 확인했다. | D / A | 오답 |
| Basic_Medical_Science_17 | 응답의 `E`는 그림 라벨인데, 선택지 키로 취급하여 유효하지 않은 문자로 처리했다. | 선택지 **A의 내용이 E**인 것을 확인하여 E를 A로 대응했다. | A / A | 정답 |
| Biology_3 | 마지막 답이 `A. increase`였고 기존 규칙이 요구한 `Answer:` 등의 접두사가 없었다. | 독립된 마지막 답의 A와 실제 선택지 내용 `increase`가 일치하는지 확인했다. | A / A | 정답 |
| Design_27 | `Final Answer: C. Etruscan` 뒤에 주석이 붙어 마지막 줄만으로 추출하지 못했다. | 최종 선택 C를 원문에서 확인하고 저장 judge 제안 및 주석 검사와 대조했다. | C / C | 정답 |
| Diagnostics_and_Laboratory_Medicine_30 | 최종 답 C 뒤에 주석이 붙어 마지막 줄이 답이 아니었다. | 명시된 최종 선택 C와 저장 judge 제안을 확인하고 뒤의 주석을 검사했다. | C / D | 오답 |
| Psychology_21 | 답이 정형화된 `Answer: D` 대신 설명 문장 안에 있었다. | 마지막 문장의 `option D is the correct answer`라는 명시적 선택을 저장 judge 제안과 대조했다. | D / D | 정답 |

유형별로는 **최종 답 뒤 주석 3개, 그림 라벨과 선택지 키 혼동 1개, 접두사 없는 문자·내용 답 1개, 문장 안의 명시적 선택 1개**다. 주석을 무조건 제거하거나 설명에서 임의의 문자를 고르는 방식은 아니다. 원문 근거와 선택지 대응을 확인하며, 모순이나 새로운 선택이 있으면 보류한다.

**추출 성공 6개가 모두 정답이라는 뜻은 아니다.** 추출이 끝난 뒤 GT와 비교한 결과 4개는 정답, 2개는 오답이었다. 따라서 전체 정답 수는 6개가 아닌 4개 증가했다. Design_27처럼 응답이 스스로 설명의 사실적 타당성을 의심하는 경우에도, 여기서는 명시적으로 선택한 최종 답만 채점하며 추론의 타당성을 보증하지 않는다.

## 남은 문제·한계

40개는 모두 원래 생성이 `finish_reason=length`, 즉 토큰 한도로 끊겨 자동 추출을 보류했다. **40개 모두 원문에 최종 답이 전혀 없다고 검증한 것은 아니다.** 끊기기 전에 이미 명시적으로 답을 확정했는지는 별도의 검토가 필요하다. 이번에는 중간 계산값이나 임시 선택을 최종 답으로 추정하지 않는 정책을 적용했다. `answer_correct=null`로 미추출을 구분하지만 기존 정책대로 전체 점수에서는 오답으로 센다.

문항 수의 관계는 **원래 미해결 객관식 81개 = 이전 추출 35개 + 이번 추출 6개 + 남은 미추출 40개**다. 따라서 점수 집계의 `scoring_unresolved=0`을 보고 81개가 모두 해결되었다고 해석하면 안 된다.

참고로 `2√2`와 GT `2.83`의 비교를 보완했던 `validation_Electronics_2`는 **주관식**이며, 위 객관식 35개·46개·81개에 포함되지 않는다. 원래 judge의 오답 판정을 이전 수식 계산·소수점 둘째 자리 반올림 규칙으로 정답으로 바꾼 사례다. 이번 파서 v2에서는 그 판정을 그대로 유지했다.

이 평가는 **최종 답 채점**이며 풀이·이미지 해석의 타당성을 검증하지 않는다. 공식 MMMU 채점 또는 judge 정확도 측정도 아니다. 실제 사례를 확인한 뒤 일반 규칙을 작성한 만큼, 새로운 데이터에서의 추출 정확도와 잘못된 수용 여부는 별도로 검증해야 한다. 문항별 예외는 넣지 않았다.

기존 과제 보고서와 코드·결과는 보존하고 이번 결과를 별도 추가했다.
